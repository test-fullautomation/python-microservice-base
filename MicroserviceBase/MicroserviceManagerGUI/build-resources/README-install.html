DevAtServGUI

Microservice Manager GUI for the gRPC + Consul + Nomad platform. This README ships with the installer; for the full developer documentation see the project repository on GitHub.

Welcome

You've installed DevAtServGUI — the desktop application that drives the Microservice Manager: connect to Consul clusters, manage Nomad jobs, browse and call gRPC services, and scaffold new service projects from the built-in wizard.

The GUI is the front-end to the MicroserviceBase framework. Services you call from this GUI register themselves in Consul on startup; this app discovers them via Consul's catalog and invokes their gRPC methods either through a built-in FastAPI bridge (browser mode) or directly (Electron mode).

Launching the app

Two ways to run the installed application:

ModeHow to startWhen to use
Desktop (Electron) Start menu → DevAtServGUI, or the desktop shortcut. Default. Native window, system tray, file pickers, etc.
Browser The installed app exposes a FastAPI bridge on http://localhost:1112. Open that URL in any browser. When you want the GUI on a different machine, or for sharing / screen-sharing.

Both modes share the same UI; the difference is the host process. Settings and connection state are persisted independently per mode.

Where things live

The installer placed files in two locations:

WhatWhere
Application binaries (this README, the .exe, bundled Python helpers) The install directory you picked during setup (default: %LOCALAPPDATA%\Programs\DevAtServGUI\; C:\Program Files\DevAtServGUI\ if installed per-machine)
Settings, plug-ins, logs, downloaded service GUIs %APPDATA%\devatservgui\
Bridge / service runtime logs %APPDATA%\devatservgui\logs\
Service plug-in cache (auto-downloaded GUI plug-ins per service) %APPDATA%\devatservgui\web\services\
Read-only vs writable: the install directory is read-only (especially for a per-machine install). All user data, settings, and downloaded plug-ins live under %APPDATA%\devatservgui\ so the app can update its own state without administrator rights.

First steps in the GUI

  1. Make sure Consul + Nomad are running. The app needs a Consul agent (typically consul agent -dev on port 8500) to discover services. The Service Network tab in the GUI can start and stop both agents for you if they're installed.
  2. Click Connect in the top-right corner and enter your Consul URL (default http://127.0.0.1:8500). Use the Detect button to auto-find a local agent.
  3. Browse services in the sidebar. Each registered service shows its host:port and tags. Click a service to load its method list (discovered via gRPC reflection).
  4. Try a method. Each method has a JSON-form Invoke panel. Click a per-service </> icon to open the multi-language client-snippet modal (Python / C++ / Robot Framework code you can copy-paste into your own scripts).
  5. Generate your own service. The Service Creator tab walks you through a 5-step wizard that emits a complete, ready-to-build service project for Python or C++.

Uninstalling

Use Windows Settings → Apps → Installed apps, search for DevAtServGUI, and uninstall. The installer removes the application files but does not remove your settings and logs at %APPDATA%\devatservgui\ — delete that folder manually if you want a fully clean removal.
