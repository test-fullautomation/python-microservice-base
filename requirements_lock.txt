# Pinned dependency set for the Bazel `@pypi` hub (see MODULE.bazel).
#
# Bazel resolves EVERY py_library / py_test dep against this file, so a
# new import in a BUILD target needs an entry here as well. That coupling
# is deliberate: it stops a target from silently depending on whatever
# the developer happens to have installed.
#
# These pins mirror pyproject.toml's floors, resolved to concrete
# versions. They are NOT taken from the current interpreter: at time of
# writing that environment still held the abandoned protobuf-3.20
# experiment (protobuf 3.20.3 alongside grpcio-tools 1.80), a
# combination we demonstrated does not work -- grpcio-reflection's
# bundled stubs require protobuf >= 5.27.
#
# Regenerate properly on a networked machine:
#     pip-compile --generate-hashes -o requirements_lock.txt requirements.txt
#
# No --generate-hashes yet because this was authored offline. Add hashes
# when regenerating -- Bazel can then verify downloads.
